##Ответы на контрольные вопросы

1.Что такое IL и зачем он нужен между C# и машинным кодом?
IL (Intermediate Language) — промежуточный байт-код, в который компилятор превращает C#-код. Он не привязан к конкретной архитектуре процессора. При запуске компилятор превращает нужные участки IL в машинный код конкретного процессора, учитывая его особенности и применяя оптимизации.

2.Почему .dll можно декомпилировать?
Потому что .NET-сборка хранит не только IL-инструкции, но и метаданные: информацию о типах, классах, методах, полях, сигнатурах. Дополнительно может лежать отладочная информация. Этого достаточно, чтобы ILSpy восстановил код, очень похожий на исходный.

3.Какие отличия Debug и Release вы увидели в IL?
В Debug присутствуют инструкции nop, четыре локальные переменные включая служебные bool и int64, условие i <= n разложено на cgt + ceq + brtrue, есть лишние переходы br.s. В Release этих элементов нет: осталось две локальные переменные, условие выражается одной ble.s, общее число инструкций уменьшилось с 28 до 16.

4. Почему Release обычно быстрее Debug?
 В Release компилятор применяет больше оптимизаций: убирает nop, лишние обращения к локальным переменным, недостижимый код, упрощает сравнения. JIT-компилятор при запуске Release-сборки тоже оптимизирует код агрессивнее. В результате получается меньше инструкций и более эффективное выполнение. Но Release не гарантирует ускорения всегда — результат зависит от кода, версии .NET, JIT и процессора.

5.Почему строковый пароль в .dll нельзя считать защищённым?
Строковые литералы хранятся внутри сборки в открытом виде (обычно в UTF-16) без шифрования. Их можно найти в HEX-редакторе (например, Hex Editor в VS Code) или увидеть при декомпиляции в ILSpy. Компиляция в .dll или .exe сама по себе не защищает секреты, поэтому пароли и ключи API нельзя хранить в коде в расчёте на то, что после сборки их никто не увидит.
